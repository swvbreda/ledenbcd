# Projecten & taken rules

Applies to /projecten UI, internal_projects/internal_tasks DB code, planner/topical/taskNotifications server functions.

- Outlook task deadlines reuse the confirmed planner_user_map and Graph app config: task/project/mapping triggers queue only future changes while enabled (existing linked rows stay tracked when paused); admin-only server dispatcher uses a release gate, bounded claims, immutable ids, conditional ETags and transactionId, and unknown writes never retry automatically. Popup is off, calendar items are all-day/free with minimal backlinks; local completion never calls Graph. Only service-role finish/configure RPCs can write event ownership/config, with explicit current-admin actor validation; no backfill. Manual and internal-secret scheduled dispatch share one bounded worker and existing claim/lease engine; scheduler actor comes only from enabled settings updated_by with a current-admin check, defaults disarmed and the reviewed service-only configure RPC atomically changes enabled/armed after install metadata and current-admin checks; disabling pauses only its own cron under the wake/drain lock, wakes only its own pending queue and disarms after drain.

- Internal 'Projecten & taken' (internal_projects/internal_tasks) is admin-only via has_role(...,'admin') RLS plus a trigger that only allows admin accounts as owner/assignee; board or member status must never grant access, and rows are archived/completed rather than deleted.
- Planner sync runs only in admin-checked server functions against one fixed target plan, one BCD project per Planner bucket (unique plan+bucket), reading tasks via the bucket endpoint with explicitly fetched details; POST is retried only on 429, uncertain creates are never auto-recreated without an admin decision, sync hashes are only stored for writes that actually landed, lock token + heartbeat + hard deadline bound each run, and nothing is ever deleted in Planner — prevents duplicates, cross-project imports and silent data loss.
- Topical-actions (internal_tasks.source_system='topical', server-owned source_ref): the task-list 'Afronden' button and editor never call Microsoft — Topical rows complete in one click via the audited RPC `topical_complete_local_only`, others via a plain update (`completeTaskLocally`); external completion lives only in the Topical tab. They complete either via the admin-only `topicalComplete` server function or the explicit audited admin RPC `topical_complete_local_only` (never fakes remote timestamps; reopening clears its audit). Full completion: original Microsoft To Do task completed + existing Planner task 100% via If-Match, local 'afgerond' allowed by trigger only after both are recorded in `topical_task_links`; generic Planner sync skips Topical tasks so imports are never duplicated and partial failures can't show false success.
- Task-assignment notifications originate only from the DB trigger on internal_tasks.assignee_id (one task_notifications row per transition, admin recipients, read-only to clients except the mark-read RPC); push delivery runs in the admin-only dispatchTaskPushes server fn with claim/attempt limits, so clients can never choose recipients and push failure never blocks saving.
- Project workspace (/projecten?project=<id>) extends internal_projects/internal_tasks with participants, append-only messages (incl. 'bronupdate' requiring source date/subject/mailbox/ref/last action/next step), checkpoints and trigger-written internal_project_events; author/actor/timestamps are forced by SECURITY DEFINER triggers (service-role inserts become 'bronimport', missing historical actors show 'Niet geregistreerd'), and claiming uses the atomic RPC `claim_internal_task` (only unassigned open tasks, only for auth.uid()) — so clients can never forge audit or steal tasks.
- Provenance: created_at (insert) and completed_at (real transition to afgerond; kept while unchanged, NULL on reopen) are forced server-side. `created_origin` (projects/tasks) and `internal_tasks.import_ref` (unique, idempotent mail/source import key, separate from Topical source_ref) are server-owned by trigger `internal_work_provenance` — authenticated inserts force created_by=auth.uid()/'medewerker'/no import_ref, service inserts become 'bronimport', updates keep old values; NULL origin = historical. Staff display names come from account name, else one unambiguous board_members email/bond_email match (display only, never auth).
- Ordinary /projecten screens never show source/import provenance: imported metadata in texts is hidden via `src/lib/presentText.ts` (display-only, DB untouched; unchanged cleaned text is never written back), bronupdates render as 'Stand van zaken' without subject/mailbox/ref/author, and the note form has no bronupdate option — backend source columns, validation and guards stay for service imports.
- Project documents live in private bucket `project-documents` at `<project_id>/<sha256>.<ext>` (PDF/DOCX/XLSX ≤20 MB) with metadata in `internal_project_documents`; admin-only has_role RLS on both, insert-only storage (no update/delete policies, so versions are never overwritten), metadata insert requires the object to exist and forces uploader/created_at, rows are immutable except soft archive — prevents public links, silent overwrites and forged uploaders.
- Project status-list fields (`planning`, `planning_date`, `status_date`, `remarks`) are plain nullable text/date edited in 'Project bewerken' and logged by `internal_project_log`; empty means 'Nog niet vastgelegd', never filled in by the app.
- Shared dossier register (`dossier_register` parent/child one level, `dossier_finance_aliases`, m:n `dossier_project_links`) is the single dossier classification for /projecten, /jaarplan (admin widget) and Financiën; admin-only has_role RLS, links are insert/delete only with server-forced actor and audit into internal_project_events. Finance labels map only by exact (trimmed) alias, never fuzzy, and booking labels/amounts are never rewritten — so finance data can't be silently regrouped. Seeded projects use server-owned `internal_projects.import_ref` (idempotent) with created_by NULL + bronimport.
- Explicit user exception (2026-10-14): current members and leads (member_profiles → members_data.member_type in ('member','lead'), not extern/inhuur) and admins may read project status + Verloop ONLY via SECURITY DEFINER RPC `get_member_project_status` (id, title, status, status_date, description, server-extracted Verloop items; archived excluded; never raw project_plan, Huidige stand, Vervolg, tasks, docs, owners, budgets, dossiers). Base tables, storage and mutation guards stay admin-only; the members UI (`MemberProjectsView`, also the admin 'Ledenweergave' preview) uses only this RPC.
- Dossier 'Algemene status' (`dossier_register.status_summary` text + `status_date` date, independently nullable) is explicitly authored by admins in the Projecten dossier overview, never derived from tasks/projects/children; authenticated may UPDATE only these columns plus `project_hidden_at` under existing admin RLS; not exposed to members (member RPC unchanged) and ignored by Jaarplan/Financiën.
- Explicit user exception (2026-10-20): published member_announcements auto-link to projects via trigger `zz_announcement_sync_projects` → `announcement_sync_projects` (whole-word case-insensitive match of non-archived dossier names ≥4 chars and project titles; dossier matches include their linked projects; >3 dossiers or projects = ambiguous, nothing linked). Per new (announcement, project) link in `announcement_project_links` (idempotent): one 'bericht' message (bronimport), project `status_date` moved forward; matched dossiers get `status_summary`=title/`status_date`. PDF attachments are copied to project-documents by the WhatsApp webhook (`announcementProjectDocs.server.ts`); photos are not (bucket only accepts PDF/DOCX/XLSX). Sync failures never block publishing.
- Teams/Outlook → app is one-way import (Microsoft leidend) via `src/lib/msImport*.ts` and service-only RPCs `ms_import_apply_agenda/_planner`: only the admin-confirmed non-default calendar of the fixed mailbox and explicitly linked buckets of the fixed plan are read (GET-only port, no write methods); imports upsert on external id only (never title/date match), new agenda items are unpublished type 'vergadering', absence is only recorded after a complete read and never deletes/archives locally. While `ms_import_settings.planner_mode='import'` (default), all generic Planner write server functions refuse and status reports canWrite=false, so auto-sync can never push.
- Projectmail (RCF): each internal_project has one permanent `project_mail_codes.reference_code` (BCD-<WORD> only when unambiguous, else BCD-<id8>; trigger on insert, no update/delete). Only mail from fixed mailbox info@ with exactly one exact case-insensitive `[BCD-…]` subject token is read (Graph GET-only inbox delta + one message body, token-only checkpoint saved after a page is fully processed, lease RPC, unique (mailbox, source id, project)); unknown/multiple/invalid/paused/archived codes, unverified/owner/deadline tasks and existing-task status go to `projectmail_reviews`; only explicit, source-quoted, owner/deadline-free new actions become unassigned tasks (idempotent import_ref). AI summaries live only in admin-only `projectmail_messages`, never in project fields, internal_project_messages or the member RPC. Connection counts only with Mail.Read/Mail.ReadWrite (never Mail.ReadBasic) plus a real GET of one message body (empty inbox: role + list). Automatic runs use own cron job `projectmail-pull` (installed inactive) whose tick sends a DB-minted single-use hashed wake token (no Vault/secret), and only `projectmail_configure` (current-admin, installed job, connection verified <15 min) sets enabled+armed and toggles only its own job atomically; non-connected checks disarm. Runs stop at RUN_BUDGET_MS (< lease) before claiming a message, AI calls are bounded by the same deadline.
