# WhatsApp and Mijn vragen rules

- WhatsApp connector verifies Lovable signatures before durable admin-only receipt; legacy keeps its Meta signature contract. Recovery runs fairly on later callbacks; no replies, sends, media or history/contact imports. Both verified paths publish every text (forwarded or own) from an explicitly admin-consented publisher to the fixed linked recipient via a service-only transaction, per-message advisory lock and private immutable decision ledger; existing announcement RLS/notifications stay unchanged. Admin server function + admin RPC manage publishers; replay/deletion never republishes.
- Forwarded WhatsApp attachments (jpg/png/pdf ≤20 MB) are published only after the full file is stored in private bucket `announcement-media` and `whatsapp_attachment_complete` re-checks the publisher; download failures, missing captions or other types stay inbox-only, so members never see an incomplete announcement.
- 'Mijn vragen' (`support_*` tables, `/mijn-vragen`, admin tab in `/whatsapp-inbox`) is private per auth user: reads via RLS (`support_member_id` = active `member_profiles`→`members_data.member_type='member'`, no extern/inhuur), all writes through checked SECURITY DEFINER RPCs; WhatsApp joins only after a hashed single-use code links sender+user (trigger on `whatsapp_messages`, never retroactive, publishers excluded), and replies go reserve→gateway→finish once with the 24h window checked in the DB — so no phone-only matching, double sends or private history leaks. Link commands (`whatsapp_is_link_command`, any `BCD-<alnum>`) are handled before the publisher exclusion and refused in `whatsapp_publish_forwarded`, so codes never become announcements; RLS uses `support_my_member_id()`, the per-uid helper is definer-only. Code consumption and support routing only run when the verified ingest sets `bcd.wa_recipient` to the fixed BCD number. Privacy tests: `support_fixture_extract.py` (live DDL into an isolated local Postgres), `support_privacy_full.sql`, `support_reserve_concurrency.sh`.
- Support UI: attachment signed URLs (60s) are minted only on explicit click, never cached in query data; the BCD recipient number comes read-only from the connector via `bcdWhatsAppNumber.functions.ts` and is accepted only for the fixed phone_number_id; WA transport errors show "unknown" and keep the clientKey (retry dedups server-side); app and WA replies use separate client keys; thread views are keyed by thread id.
